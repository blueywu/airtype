# AirType：按应用使用状态开麦

分支 `codex/microphone-follow`，基于 `codex/voice-actions` 的 `321e0e2`。仅本地 Git；不合并 main、不上传、不安装或替换现有应用和驱动。

## 使用顺序

1. 在录音应用中选择 `vRemoteDr 2ch`；应用使用系统输入时，在系统声音设置中选择该设备。
2. 打开 AirType「麦克风」，选择启用方式。
   - **自动跟随**：任意应用开始使用该设备后开麦，最后一个应用停止后关麦。
   - **指定应用**：名单内任意应用开始使用该设备后开麦，最后一个名单内应用停止后关麦。空名单不会自动开麦。
3. 指定应用用「添加应用…」或「系统应用…」选择。本机任意位置的 `.app` 均可多选；用 ⇧⌘G 前往其他目录。包括语音备忘录等系统应用，不要求配置快捷键。
4. 需要遥控器控制时，在「快捷键」配置 Typeless/Codex 等预设，在「按键」绑定对应动作，或直接录制自定义按键。这里的服务列表不限制麦克风应用名单。
5. 鼠标、键盘和遥控器均可控制录音。暂停遥控器麦克风后，要手动恢复自动跟随。

## 生命周期与边界

- CoreAudio 实际输入进程与输入设备共同决定开麦，不以默认设备选择、前台应用或快捷键推测录音。
- 多应用共享麦克风，不发送“停止上一个应用”的快捷键。450ms 释放防抖避免短暂进程切换导致闪断。
- 排除 AirType 自身的音频写入，避免自我维持。嵌套 helper 按进程路径归到外层 `.app`；路径不可用时使用 Bundle ID 后缀匹配。
- 首帧超时会关闭并重试；最多三次请求后提示检查连接，重连或暂停/恢复可重置。
- 名单只控制遥控器何时开麦，不是操作系统级音频访问隔离。开麦期间，其他获准使用麦克风的应用可能读取相同设备。
- 应用预览音量、暂停录音后保留输入流，也会被视为使用麦克风。AirType 无法据此判断是否正在保存录音。
- 物理语音键可能先由遥控器固件启动音频，再由 AirType 判断需求。蓝牙开麦有启动延迟；未做首字完整性保证。
- 浏览器网页按浏览器应用处理；独立系统代理、跨应用共享录音服务的归属需要真实应用验证，不能承诺所有进程架构均已覆盖。

## 本地记录

开关、保存目录和隐私规则沿用 P1；默认关闭。新增记录按实际使用设备的应用分别计时，同一应用 helper 去重，并发应用分别保存。服务字段为“麦克风使用”，来源为“application”。记录时间包含预览、静音和停顿，不表示成功转写时长；不推测最终文字输入到哪个应用，也不保存音频或文字。

旧 VoiceActionRouter/X6SessionCoordinator 文件保留作为历史实现与回归参考，AppController 当前使用 MicrophoneFollowController，不调用旧的互斥会话路由。
