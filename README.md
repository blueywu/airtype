# AirType

首先感谢原作者 [VincentKingHsu](https://github.com/VincentKingHsu/vRemoter) 创建 vRemoter。AirType 基于 [ccc333cn](https://github.com/ccc333cn/vRemoter) 的 PR 分支继续开发，也感谢他对原项目的改进。

把蓝牙遥控器变成 Mac 上的小键盘，也可以把它当作麦克风。

AirType 常驻菜单栏。你可以用遥控器复制、粘贴、执行自定义快捷键；需要语音输入时，再开启遥控器麦克风，把声音交给 Typeless、Codex 等应用处理。

AirType 负责按键映射和音频桥接，不负责语音识别。按键和音频处理在本机完成；听写软件是否联网、如何处理声音，由该软件自己的设置和服务决定。

## 可以做什么

- **按键映射**：常用快捷键预设、自定义按键录制，区分左右修饰键；配置按遥控器型号保存。
- **遥控器收音**：将遥控器声音送进虚拟麦克风 `vRemoteDr 2ch`，供录音或听写应用选择。
- **语音动作**：为不同应用分别配置听写快捷键，再绑定到遥控器按钮。
- **按使用情况开麦**：跟随所有使用 AirType 麦克风的应用，或只允许语音动作及额外应用触发。多个应用可以同时读取，最后一个停止使用后关麦。
- **本地使用记录**：可选记录、导出和清空；查看近 7 天或 30 天的每日堆叠时长、App 累计时长和时长占比。
- **外观**：原生半透明窗口，支持跟随系统、浅色和深色。右上角的外观按钮独立于三个设置页面，选择会保存在本机。

## 支持范围

当前接入以下遥控器：

| 设备 | USB/HID 标识 |
| --- | --- |
| Google Chromecast Voice Remote | VID `0x18D1` / PID `0x9450` |
| X6 Remote | VID `0x1D5A` / PID `0xC081` |

其他型号，包括不同代的 Google TV 遥控器，不能仅凭外观或商品名称判断兼容。X6 的部分功能由设备固件内部处理，无法单独映射。

内置语音动作支持 **Typeless、Codex、豆包输入法、微信输入法**。这些是快捷键与应用状态的适配，不包含对应应用的安装或语音识别服务。

其他录音应用可以通过“全局”或“语音动作及额外应用”使用 AirType 麦克风，无需专用语音动作。新增应用适配欢迎提交 [Issue](https://github.com/blueywu/airtype/issues) 或 [Pull Request](https://github.com/blueywu/airtype/pulls)。

## 安装与更新

按键功能需要支持的遥控器、蓝牙连接及相应系统权限。遥控器收音还需要安装音频驱动，使系统中出现 `vRemoteDr 2ch`。

**首次使用**：在 macOS 蓝牙设置中配对遥控器，将 `AirType.app` 放入“应用程序”后打开。根据“窗口顶部 → 设备与权限”的提示，检查辅助功能、输入监控、蓝牙及所需的麦克风权限。驱动构建与安装说明见 [Driver/README.md](Driver/README.md)。单独的 App ZIP 不包含驱动。

**替换已有版本**：结束听写，从菜单栏退出 AirType，将新版 `AirType.app` 拖到“应用程序”并替换，再从该目录打开。同一个设备上正常替换应用会沿用原有偏好和记录；驱动未变时无需重装驱动。系统若要求重新授权，按实际提示处理。

构建脚本使用 ad-hoc 签名，不包含 Developer ID 签名或 Apple 公证。

## 三个设置页面

### 1. 按键映射

先选遥控器型号，再开启“启用按键控制”。可以选择常用操作，也可以点击“录制”捕捉自定义组合键。恢复默认前会提示影响范围，只重置当前型号。

只想把遥控器当小键盘时，关闭“语音设置”右上角的“遥控器麦克风”即可。普通按键直接发送快捷键，录音仍使用目标应用自己的输入选择。已保存的应用语音绑定在此模式下也只发送对应快捷键，不由 AirType 主动接管输入。

### 2. 语音设置

右上角的“遥控器麦克风”是总开关。开启后，再选择开麦方式和语音动作。

| 开麦方式 | 什么时候启用遥控器麦克风 |
| --- | --- |
| 全局 | 任意应用实际开始读取 AirType 麦克风时开启；全部停止使用后关闭。 |
| 语音动作及额外应用 | 已启用语音动作的应用，或额外名单中的应用实际读取 AirType 麦克风时开启。 |

从键盘、鼠标或遥控器启动录音都可以触发上述行为。前提是录音应用实际使用 `vRemoteDr 2ch`；仅把它选为系统输入，不会持续开麦。

要让遥控器按钮主动启动听写：在“语音动作”中录制与目标应用一致的快捷键、启用该动作，再到“按键映射”绑定。AirType 会准备音源、临时选择虚拟输入，再发送听写快捷键；会话结束后尝试恢复原输入。用户中途手动选择的新输入不会被强行改回。

**Codex 语音动作目前要求 Codex 位于前台。** 它不是在任意应用前台都能启动的全局听写入口。

“额外允许的应用”位于语音动作下方，仅用于补充其他录音应用。已启用的语音动作应用自动允许，无需重复添加；全局模式下额外名单不限制开麦范围。

顶部盾牌图标打开设备与权限，缺少权限或设备时显示橙色提醒；外观图标点击后直接展开选择菜单。

页面标题旁的问号提供场景和系统设备说明，可悬停或点击查看。

最底部保留两个低频选项：

- **保持音频通道开启**：用于按需音频不稳定时的兼容选项，通常保持关闭。
- **MacBook 麦克风（Beta）**：可选内置麦克风混音，默认关闭，仅在遥控器麦克风开启后可见。实验性功能；内置麦克风不可用时跳过。

### 3. 使用记录

记录默认关闭，开启后开始积累。关闭后停止新增，已有历史保留；可以导出 JSON 或清空。

图表只汇总已有记录，不会补造安装前的数据：

- 堆叠柱状图按本地日历和会话开始日期汇总使用时长，按应用分色。
- App 占比按已知使用时长计算，同时显示累计时长；前五名之外合并为“其他应用”。
- 未确认的会话不计入图表；中断后未知的时长不补算。

麦克风使用可能包含预览和停顿；多个应用同时读取时，记录时长可能重叠。它不是净说话时间、语音识别准确率，也不代表文字最终输入到了哪个应用。

## 音频设备与常见疑问

**为什么声音输出里也能看到 `vRemoteDr 2ch`？**

它是驱动提供的虚拟音频设备，可能同时出现在系统输入和输出列表。录音应用应把它选作输入；播放仍选择实际扬声器或耳机。误把虚拟设备选作播放输出，可能听不到声音。

**语音动作及额外应用模式会隐藏设备，或阻止其他应用读取吗？**

不会。它决定谁能触发开麦，不是系统级的音频访问隔离。开麦期间，其他有权限且选择同一输入的应用仍可能读取声音。

**关闭遥控器麦克风后，为什么听写没声音？**

检查目标应用是否仍选择 `vRemoteDr 2ch`。关闭 AirType 收音不会自动替你挑另一只麦克风，需要将该应用切回实际输入设备。

**遥控器已经连接，为什么不亮录音灯？**

连接、选中设备、实际使用麦克风是不同状态。先检查总开关，再确认应用选择 AirType 输入并开始使用；语音动作及额外应用模式还需检查对应动作或名单。某些应用停止保存录音后仍保持麦克风预览，可能继续触发开麦。

## 本地数据与联网

AirType 不上传录音或识别文字，不包含遥测统计。蓝牙用于连接遥控器；项目反馈链接由浏览器打开 GitHub。

使用记录只保存时间、时长、应用标识和会话状态等元数据，不保存音频、识别文字、窗口标题、网页地址或剪贴板。连接与音频状态日志也保存在本机。

## 从源码构建

需要 macOS、Xcode 或兼容的 Command Line Tools 与 Swift 工具链。在仓库目录执行：

```sh
swift build
./package-app.sh
```

打包结果为 `dist/build/AirType.app`。构建不会自动安装应用或音频驱动。
